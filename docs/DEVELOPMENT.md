# 开发规范

## 版本与发布

- 当前基线为 `ver1.0.1`。功能更新将第二段加一并将第三段重置为 `1`；没有功能更新的修复、优化或打包调整只将第三段加一。同一发布仅递增一次，重新编译和测试不递增。
- 编辑 `Directory.Build.props` 的 `Version`，并同步 `src/UsbHub.App/app.manifest` 的 `assemblyIdentity` 四段版本（例如 `1.0.1.0`）。界面读取程序集版本，构建脚本读取统一版本配置并核对 manifest 与 EXE 版本。
- `scripts/Build.ps1 -SelfContained` 输出 `artifacts/usbHub-ver<版本>-win-x64.zip`；不带开关时输出 `usbHub-ver<版本>-win-x64-framework-dependent.zip`，两种包不会互相覆盖。
- `Portable.pubxml` 将运行文件打包为单个 EXE，仅保留简体/繁体中文资源与英文回退，不复制 PDB。自包含版启用内嵌压缩；保留完整运行库代码，不使用 WPF 不支持的程序集裁剪。
- ZIP 只含 `UsbHub.exe` 和生成的 `使用说明.txt`。开发文档、源码、测试、预览、设备扫描结果和用户设置不入包。每次发布使用全新临时目录并在结束后清理，避免混入历史 DLL 或不同运行库模式的残留文件。
- 发布验证须从新 ZIP 解压到独立目录，核对文件清单、EXE 版本并执行默认离屏 `--preview` 检查；不要停止或覆盖用户正在运行的实例。

## Windows 集成

- 使用普通用户权限（manifest `asInvoker`）、Per-Monitor V2 DPI、Unicode、系统字体和可调整大小的原生窗口。主窗口使用 `WindowStyle=None` 配合 `WindowChrome`（`GlassFrameThickness=0`），仅绘制自定义标题按钮，避免系统按钮叠影及隐藏/恢复后的残留；保留原生缩放、系统菜单及贴靠命中测试。
- 使用公开的 Windows API；系统材质通过 `DWMWA_SYSTEMBACKDROP_TYPE` 接入。尊重透明效果和高对比度开关，界面不依赖持续动画。
- 保留最小化、最大化、还原、系统菜单、托盘和单实例恢复；最大化按钮提供 `HTMAXBUTTON` 命中测试以接入 Windows 11 Snap Layout。
- 控件使用标准 Button / RadioButton / CheckBox / Slider，搜索框和图标按钮提供辅助功能名称。完整 Narrator、各 DPI、各 Windows 高对比度主题和 Snap 悬停的人工验收仍需执行，不能仅凭构建成功宣称已完成。
- 不自动开启自启、服务或管理员权限。托盘退出必须停止扫描并释放设备句柄。

## 代码组织

- Core 不引用 UI 或 Windows SDK。设备读取实现 `IBatteryProvider`，展示逻辑位于 ViewModel。
- 启用 nullable、编译警告视为错误、确定性编译及 .NET 分析器；遵循根目录 `.editorconfig`。
- 使用 SafeHandle / using 释放文件句柄、蓝牙对象和非托管内存。阻塞驱动调用放在独立扫描进程，不在 UI 线程轮询。
- 不对磁盘个人目录初始化 Git；如后续需要版本控制，仅允许当前明确授权的项目根目录，写入前确认仓库根目录。

## 电量数据约束

- `null` 表示未知，`0` 表示真实空电量。拒绝越界、无效范围和协议 NAK，不钳制为 0% / 100%。
- 保留百分比和粗略等级的区别。绝对容量需同时读取 Full Charge Capacity，不能直接当百分比。
- PnP 存在不代表无线连接。系统维护属性不是已知更新时间的实时读数；标记缓存，不发提醒。
- 同一容器的多个来源合并，实时值优于缓存；不按设备名称或 VID/PID 合并不同硬件。厂商接收器不同槽位保留独立标识。
- 扫描失败保留的旧数据标记为缓存，不再触发通知。
- 所有设备的主动读取必须经过 `ActiveScanSchedule`，每 1800 秒最多一轮；定时、手动、插拔、恢复和公开诊断入口共用持久化计划和进程锁。开始查询前占用本轮，失败或重启也不能绕过冷却。原生 `--scan-worker` 仅为调度器启动的隔离工作进程入口。
- 只对已知厂商控制集合发送已核对的电量查询命令。禁止尝试未知 opcode、固件升级、配对、复位、按键/灯光/音效配置写入。
- 不采集键盘输入流。通用 HID 仅在报告描述符声明电量字段时执行 GetFeature / GetInputReport；厂商读流限定在已识别的控制集合。

## 验证

- 核心测试覆盖未知/零电量、范围换算、容量、缓存/离线/过期抑制、冷却与恢复、设备合并、协议响应匹配、设置损坏和型号识别；主动查询限频使用模拟时间和假读取器验证 30 分钟边界、重启、失败、并发和缓存，不访问外设。
- 默认 UI 测试在隔离数据目录和屏幕外运行，托盘内容直接离屏渲染 PNG，验证搜索/筛选/空状态、设置读写，以及零电量、未知、等级、缓存和充电状态；检查主窗口三轮隐藏/恢复后的原生样式、托盘合成右键回调、忽略悬停、操作按钮、紧凑布局和不透明回退。不注册托盘、不弹出菜单、不激活窗口、不操作鼠标键盘、不发送通知、不修改外设。仅在用户明确允许交互测试后，使用 `scripts/Test.ps1 -InteractiveTray` 显式开启托盘注册与实际面板显示检查；该模式需要交互式 Windows 桌面，会短暂显示并激活右键面板。
- 新适配必须记录型号、VID/PID、usage、报告尺寸、命令来源和真实硬件读取结果。识别到型号不等于电量读取已支持。
- 编译或模拟检查不能替代真实连接、插拔、充电状态变化和低电量通知验收。
